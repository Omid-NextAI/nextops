# گفت‌وگوهای ذخیره‌شده: بهره‌برداری و پذیرش

[English](../en/CONVERSATIONS.md) · [مشخصات](CONVERSATION_MEMORY_SPEC.md)

در ۹ مهر ۱۴۰۵ فقط کد نامزد موجود است؛ این قابلیت‌ها در نسخهٔ در حال خدمت غیرفعال‌اند.
گردش‌کار UI/UX به طراحی سابقهٔ قابل‌استفاده با صفحه‌کلید کمک کرده و نشان و رنگ‌های OCS ثابت‌اند.

## رفتار کاربری

پس از پذیرش و فعال‌سازی، گفت‌وگوی عمومی در PostgreSQL محلی برای حساب شما ذخیره می‌شود. برای
ادامه، گفت‌وگو را از نوار کناری انتخاب کنید. «گفت‌وگوی تازه» موارد قبلی را حذف نمی‌کند؛
«حذف این گفت‌وگو» متن همان مورد را صریحاً پاک می‌کند. خروج، محتوای خصوصی صفحه و توکن مرورگر را
پاک می‌کند، نه سابقهٔ ذخیره‌شده را. گذرواژه، کلید یا اطلاعات محرمانه وارد نکنید.

صفحه حداکثر ۱۲ پرسش‌وپاسخ را نشان می‌دهد. هر صفحهٔ API حداکثر ۲۰ مورد دارد و before_sequence
برای موارد قدیمی‌تر است. مدل حداکثر شش جفت کامل و پذیرفته‌شده را در سقف ۱۲ هزار نویسه می‌بیند.
اگر کنار گذاشتن زمینه اعلام شد، جزئیات لازم را دوباره بیان کنید. پاسخ ذخیره‌شده، تولید تازه
نیست. حافظهٔ عمومی شاهد وضعیت فعلی سرور نیست؛ حالت‌های زنده همچنان شاهد تازه و مجاز می‌گیرند.

حالت «معمولی» پیش‌فرض است. «بررسی بیشتر» فقط پس از پذیرش اپراتور نمایش داده می‌شود. استدلال
خصوصی کنار گذاشته و فقط پاسخ نهایی نمایش و ذخیره می‌شود؛ ممکن است کندتر یا همچنان نادرست باشد.
این قابلیت، استنتاج و ذخیرهٔ گفت‌وگو است، نه آموزش مدل.

## مرجع API و تنظیمات

همهٔ مسیرها نشست معتبرِ bearer می‌خواهند؛ دانستن شناسه به‌تنهایی مجوز نیست.

| مسیر | قرارداد |
| --- | --- |
| GET /api/v1/conversations/config | گزینه‌های فعال‌سازی، استدلال، زمینه و نگهداری |
| POST /api/v1/conversations | locale؛ ایجاد گفت‌وگوی خالی برای مالک |
| GET /api/v1/conversations | حداکثر ۵۰ خلاصهٔ مالک، از تازه به قدیمی |
| GET /api/v1/conversations/{id} | ۲۰ مورد آخر؛ before_sequence اختیاری از ۱ تا ۱۰۱ |
| POST /api/v1/conversations/{id}/messages | request_id از نوع UUID، زبان، پرسش ۱ تا ۴۰۰۰ نویسه و انتخاب استدلال |
| DELETE /api/v1/conversations/{id} | حذف صریح متن؛ فرادادهٔ ممیزی باقی می‌ماند |

مسیر قدیمی /assistant/generate و قراردادهای زنده سقف قبلی را حفظ می‌کنند. تکرار درخواست
کامل‌شده همان پاسخ ذخیره‌شده را می‌دهد. درخواست هم‌زمان تعارض است. پس از خرابی مدل، اگر همان
نشست هنوز معتبر باشد، مهلت پردازش پاک می‌شود. درخواست لغوشده یا فرایند متوقف‌شده پس از ۵۴۰
ثانیه منقضی می‌شود؛ تلاش خودکار و نامحدود وجود ندارد.

گزینه‌های برنامه: NEXTOPS_CONVERSATIONS_ENABLED=1 و فقط پس از پذیرش،
NEXTOPS_CHAT_THINKING_ENABLED=1. گزینه‌های AI: ‏NEXTOPS_EXPANDED_CHAT_ENABLED=1 و فقط پس از
پذیرش NEXTOPS_THINKING_ENABLED=1. مقدار NEXTOPS_CONTEXT_TOKENS=16384 باید با n_ctx واقعی
runtime یکسان باشد. پیش‌فرض‌ها غیرفعال و ۸۱۹۲ هستند. برای پذیرش اولیه همان مهلت تولید ۱۲۰
ثانیه حفظ شود؛ اگر پاسخ طولانی‌تر در آن تکمیل نشد، نمایهٔ تازه به تصمیم جداگانه و مبتنی بر
اندازه‌گیری نیاز دارد. افزایش مهلت نباید شکست آزمون را به موفقیت تبدیل کند.

## ترتیب استقرار و بازگشت

1. نسخهٔ دقیق برنامه، API هوش مصنوعی، فایل و drop-in انتخاب مدل و هش فایل‌ها حفظ شوند.
2. مهاجرت افزایشی 0003 با نقش محافظت‌شدهٔ مهاجرت و روند استقرارِ بازبینی‌شده اجرا شود؛ نشانی
   پایگاه دارای اطلاعات محرمانه در خط فرمان قرار نگیرد.
3. بستهٔ دقیق و آزموده‌شدهٔ برنامه و AI با گزینه‌های غیرفعال نصب شود؛ مسیرهای قبلی سالم بمانند.
4. drop-in نامزد با زمینهٔ ۱۶۳۸۴، شانزده رشته، یک slot، صفر لایهٔ GPU، سقف استدلال ۳۸۴ توکن
   و بدون حفظ استدلال سنجیده شود. آزمون نخست با سقف ۱۰۲۴، به خطای مستقلِ مهلت ۳۰ثانیه‌ای
   پراکسی رسید و بدون پاسخ نهایی تا مهلت ۱۲۰ثانیه‌ای مدل ادامه یافت. با سرعتِ مشاهده‌شدهٔ حدود
   هشت توکن در ثانیه، نمایهٔ کم‌حجم‌تر زمانی برای پاسخ نهایی باقی می‌گذارد؛ پذیرش آن همچنان
   جداگانه لازم است. محدودیت‌های سرویس، منابع و شبکه به ارث می‌رسند و گزینهٔ
   دانلود زمان اجرا وجود ندارد. قالب و توکن‌بندی واقعی روی runtime کنونی موفق‌اند؛ این آزمون
   هیچ پاسخ دارای استدلال تولید یا تأیید نکرده است.
5. گزینه‌های هماهنگ فقط پس از سنجش ارتباط پاسخ فارسی/انگلیسی، پیگیری، جداسازی منشأ، تأخیر،
   شکست، مجوز، کارکرد آفلاین و بازگشت فعال شوند؛ شناسه و نتیجهٔ دقیق ثبت شود.
6. برای بازگشت، گزینه‌ها غیرفعال و برنامه، API و نمایهٔ runtime قبلی برگردند. جدول‌ها برای حفظ
   متن باقی بمانند؛ downgrade مخرب، خروجی محافظت‌شده و اجازهٔ جداگانه می‌خواهد.

مسیر پیامِ ذخیره‌شده باید سیاستِ موجودِ پراکسیِ استنتاج را داشته باشد: مهلت انتقال ۱۸۰ ثانیه
و همان محدودیت نرخ درخواست، نه مهلت عمومیِ ۳۰ثانیه‌ای صفحه. مهلت مدلِ ۱۲۰ثانیه‌ای، سقف صف و
احراز هویت تغییر نمی‌کنند. هنگام بازگشتِ هماهنگ، تنظیم دقیقِ قبلیِ پراکسی نیز برگردد.

رکورد صرفاً پژوهشی 122B دو فایل به مجموع ۷۷٬۶۱۶٬۵۱۱٬۲۹۶ بایت را پین می‌کند. منشأ تبدیل،
خود فایل‌ها، قالب، تأخیر CPU و کیفیت هنوز تأیید نشده‌اند. افزایش vCPU به‌تنهایی دلیل افزایش
تعداد رشته‌ها نیست. بررسی کنونی مهمان: ۶۴ vCPU، حافظهٔ قابل‌استفادهٔ ۱۹۳۱۸۵ MiB و یک گرهٔ NUMA
قابل‌مشاهده؛ جای‌گذاری و رزرو واقعی میزبان معلوم نیست. پیش از شاهد benchmark دوباره منابع را
تغییر ندهید.
