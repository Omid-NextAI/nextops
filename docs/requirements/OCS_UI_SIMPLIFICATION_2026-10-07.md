# OCS interface simplification / ساده‌سازی رابط OCS

## English

### Problem, precedence and scope

The owner reported a crowded workspace, overlapping controls, inconsistent button states and
unwanted login animation. This bounded source change starts from reviewed source `775797a`;
serving app/API `ec1ed32` and the release manifest are not changed. The latest request supersedes
the older reference's violet product accents and Signal Gate scene, not its security guarantees.
No deployment, infrastructure, model, prompt, policy, dependency or database change is included.

### Design inputs and requirements

The supplied video was inspected at several frames: an angled geometric background and a split
glass login card. Adopt that composition, not its unsupported sign-up or account-reset controls.
Do not embed the video, recreate another authentication system or download runtime assets.

Both supplied company JPEGs are packaged unchanged, with their original proportions and colors:

| Local asset | SHA-256 |
|---|---|
| `ocs-logo-dark.jpg` | `46ddba23a4b55f5f35d90bd4f41f1fe8f6e35bcc3c396931e58be219ffff072d` |
| `ocs-logo-light.jpg` | `e9f6390b99b971d996dbb3e3d777d4efb53ac5d4823124fa12a142bbc6716c48` |

These are owner-supplied images, not an independently verified brand manual. Keep repository
teal `#0090A0`, gold `#D0A840` and green `#5D8B43`; use separate accessible semantic colors.
Use a static logo-led login, with no gate animation, motion framework or GPU requirement.
Keep native form semantics, password managers, paste, password visibility and clear error states.

The workspace opens as a compact chat. Keep the seven navigation destinations, owner-scoped
history, actual model metadata and explicit modes. Source/approved-host selection stays visible in
live monitoring. Collapse monitoring summary, evidence rows and recorded request details; open
the inspector only on demand. Remove empty invented findings and the unsupported attachment
control from the visible interface. Missing data remains unavailable, not a healthy-looking fixture.
Use shorter EN/FA interface copy without rewriting model answers or their technical identifiers.

### Implementation and task breakdown

1. Inspect source, API contracts, existing tests and supplied design inputs; capture the old UI.
2. Replace corporate login markup/styles and copy the original light/dark assets.
3. Replace the workspace stylesheet with scoped company tokens and responsive chat geometry.
4. Synchronize busy/header/summary states, model labels after resume, locale/password controls,
   theme actions and evidence focus. Make options expand inline without covering mode buttons.
5. Test authentication, saved chats, source selection, evidence, cancellation, RTL, themes,
   responsiveness and static/reduced-motion login. Capture and inspect two refinement passes.
6. Update paired guides, this record and the context index. Keep live qualification history intact.

### Threat considerations and acceptance

Authentication, session lifetime, authorization, owner isolation, audit/provenance, safe rendering
and bounded generation remain backend-enforced. No public sign-up, target token, persistent
browser transcript, new service worker, remote font/CDN or CSP relaxation is introduced.
The fixture preview is loopback-only and visibly labelled “Demo data — not live”; the production
application never imports it. Asset packaging continues through `static/*`.

Acceptance requires unchanged brand bytes; working login/error/logout/expiry; no sensitive view
after logout; saved resume and actual model identity; synchronized busy states without duplicate
requests; enabled source/host restrictions; evidence selection, tabs, copy and focus restoration;
IME/drafts/cancellation; stale/partial/missing data; EN/FA and LTR/RTL; themes; five viewports and
200% reflow; no external runtime requests in fresh fixture browser contexts. Fixture passes do
not qualify actual model correctness, live MCP, VM restart or server-WAN operation.

### Verification and rollback

Use the [English](../en/REFERENCE_UI.md) and [Persian](../fa/REFERENCE_UI.md) handoff for exact
local commands and observed results. Preserve failed initial checks: the first helper expected
the removed header logo; later checks assumed always-open evidence and a single logo for both
themes. A real options overlap was repaired. Tests now follow deliberate disclosures and verify
original theme-specific assets, without removing authorization or failure assertions.

Screenshots under ignored `artifacts/ocs-redesign/` include before, first-pass, refined dark/light,
desktop/mobile, Persian and static login views. They contain sanitized fixtures, never live facts.
Source rollback is a reviewed revert of this bounded UI change followed by tests and rebuilding
the application package. Do not reset unrelated work. Any live package promotion/rollback is a
separate authorized change window; these source results do not establish a new deployed release.

## فارسی

### مسئله، تقدم و دامنه

مالک، شلوغی رابط، پوشاندن دکمه‌ها، ناهماهنگی وضعیت و حرکت نامطلوب ورود را گزارش کرد.
این تغییر محدودِ کد از `775797a` آغاز می‌شود؛ برنامه/API مستقرِ `ec1ed32` و رکورد انتشار
تغییر نمی‌کنند. درخواست تازه، رنگ بنفش محصول و صحنهٔ Signal Gate مرجع قبلی را کنار می‌گذارد،
نه تضمین‌های امنیتی آن را. استقرار، زیرساخت، مدل، پرامپت، سیاست، وابستگی و پایگاه تغییر نمی‌کنند.

### ورودی طراحی و نیازمندی‌ها

ویدئوی مالک در چند قاب بررسی شد: زمینهٔ هندسیِ مایل و کارت شیشه‌ایِ دو بخش. این ترکیب الهام
چیدمان است، نه مجوز افزودن ثبت‌نام یا بازیابی حسابِ پشتیبانی‌نشده. ویدئو در برنامه قرار نمی‌گیرد
و سامانهٔ ورود یا دریافت اینترنتیِ زمان اجرا اضافه نمی‌شود.

دو JPEG شرکتیِ جدول بالا با همان بایت، نسبت و رنگ اصلی بسته‌بندی شده‌اند. این‌ها تصاویر
ارائه‌شدهٔ مالک‌اند، نه راهنمای رسمیِ مستقل‌تأییدشده. فیروزه‌ای `#0090A0`، طلایی `#D0A840`
و سبز `#5D8B43` مخزن حفظ می‌شوند و رنگ معناییِ دسترس‌پذیر جداست. ورود ثابت و مبتنی بر نشان
است؛ حرکت دروازه، چارچوب حرکت و نیاز GPU حذف می‌شوند. فرم واقعی، مدیر رمز، paste، نمایش رمز
و خطاهای روشن باقی می‌مانند.

فضای کار با گفت‌وگوی ساده باز می‌شود. هفت مقصد، سابقهٔ مختص مالک، مدل واقعی و انتخاب صریح
حالت حفظ می‌شوند؛ منبع و میزبان مجاز در پایش زنده آشکارند. خلاصهٔ پایش، ردیف شاهد و جزئیات
درخواست بازشونده‌اند و پنل شاهد فقط با انتخاب کاربر باز می‌شود. کارت نتیجهٔ ساختگی/خالی و
دکمهٔ پیوستِ پشتیبانی‌نشده در نمای اصلی نیستند. دادهٔ غایب، ناموجود می‌ماند. متن رابط فارسی
و انگلیسی کوتاه‌تر است؛ پاسخ مدل و شناسهٔ فنی بازنویسی نمی‌شوند.

### مراحل پیاده‌سازی

۱. بررسی کد، قرارداد API، آزمون و ورودی طراحی؛ ثبت تصویر قبلی.
۲. جایگزینی ورود و افزودن نشان‌های اصلیِ روشن/تیره.
۳. جایگزینی stylesheet فضای کار با قواعد شرکتی و چیدمان واکنش‌گرا.
۴. هماهنگی وضعیت درخواست، مدل پس از بازگشایی، زبانِ رمز، دکمهٔ تم و فوکوس شاهد؛ گزینه‌ها
در جریان صفحه باز می‌شوند و دکمهٔ حالت را نمی‌پوشانند.
۵. آزمون ورود، سابقه، منبع، شاهد، لغو، RTL، تم، اندازه‌ها و ورود ثابت؛ دو دور مشاهده/اصلاح.
۶. به‌روزرسانی راهنماهای جفت، این رکورد و فهرست؛ حفظ سابقهٔ پذیرش زنده.

### تهدید و پذیرش

ورود، عمر نشست، مجوز، جداسازی مالک، ممیزی/منشأ، نمایش امن و سقف تولید همچنان در backend
اجرا می‌شوند. ثبت‌نام عمومی، توکن مقصد، ذخیرهٔ متن در مرورگر، service worker، فونت/CDN
بیرونی یا تضعیف CSP اضافه نشده است. پیش‌نمایش فقط loopback و دارای برچسب دادهٔ نمایشی است؛
برنامهٔ عملیاتی آن را import نمی‌کند. بسته‌بندی دارایی‌ها همچنان با `static/*` است.

پذیرش شامل تطبیق بایت نشان، ورود/خطا/خروج/انقضا، پاک‌شدن نمای حساس، بازگشایی سابقه و مدل
واقعی، وضعیت هماهنگ بدون درخواست تکراری، محدودیت منبع/میزبان، انتخاب/زبانه/کپی/فوکوس شاهد،
IME/پیش‌نویس/لغو، دادهٔ قدیمی/ناقص/غایب، زبان و جهت، تم، پنج اندازه و بازچینی ۲۰۰٪ و نبود
درخواست بیرونی در مرورگر تازهٔ آزمایشی است. این‌ها پذیرش صحت مدل، MCP زنده، reboot یا WAN سرور نیستند.

### بررسی و بازگشت

فرمان و نتیجه در راهنماهای انگلیسی و فارسیِ بالا ثبت می‌شود. شکست‌های اولیه حفظ‌اند:
helper نشانِ سربرگ حذف‌شده را انتظار داشت و آزمون‌های بعدی فرضِ شاهد همیشه‌باز و نشان یکسان
در هر دو تم داشتند. هم‌پوشانی واقعیِ گزینه‌ها اصلاح شد. آزمون جدید، بازکردن صریح و نشان اصلی
هر تم را بررسی می‌کند؛ کنترل مجوز و شکست حذف نشده است.

تصاویرِ قبل، دور نخست، نسخهٔ اصلاح‌شدهٔ روشن/تیره، دسکتاپ/موبایل، فارسی و ورود ثابت در
`artifacts/ocs-redesign/` نادیده‌گرفته‌شده‌اند؛ همگی ساختگی و پالایش‌شده‌اند.
بازگشت کد، revert بازبینی‌شدهٔ همین تغییر، آزمون و ساخت دوبارهٔ بسته است؛ کار نامرتبط reset
نمی‌شود. هر استقرار/بازگشت زنده مجوز جدا می‌خواهد؛ نتیجهٔ کد به معنی انتشار تازهٔ مستقر نیست.
